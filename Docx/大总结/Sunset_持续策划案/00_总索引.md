# Sunset 持续策划案总索引

> README 负责让人先看见游戏；这套策划案负责说明《Sunset》为什么能继续长成一款完整作品。

## 1. 这份索引给谁看

如果你是从 GitHub 页面点进来的，建议先把它当作《Sunset》的设计地图，而不是第二份 README。

- 想快速判断作品：先看仓库根目录的 `README.md`、演示视频和 Windows 试玩包。
- 想看策划思路：从 `01_总览.md` 开始，再读经营成长、交互系统和剧情 NPC。
- 想看项目体量：读 `08_进度总表.md`，再回到对应分卷看细节。
- 想接开发：这套策划案只负责设计口径，工程入口请继续看 `.kiro/about/01_系统架构与代码全景.md`。

一句话说清：README 是作品门面，这里是设计骨架；两者服务同一个项目，但读法不一样。

## 2. 当前公开口径

当前公开试玩版开放的是 Day1 完整路线：被救起、入村、疗伤、工作台闪回、采集开垦、制作整理、晚饭冲突和夜间自由活动。

这套策划案会同时记录两类内容：

1. 已经进入当前试玩版或已有运行时承载的内容。
2. 后续版本会继续扩展的设计方向。

所以读后续分卷时要注意：它们不是在假装所有内容都已经完整开放，而是在把《Sunset》的世界、系统和长期方向放到同一张设计图里。当前能直接试玩到什么，以 README 和 Release 包为准；后续会长成什么，以本套策划案承接。

## 3. 作品设计核心

《Sunset》的设计不是“种田 + 背包 + 剧情”的功能拼盘，而是围绕一个问题展开：一个失忆的外来者，怎样靠劳动、制作、关系和记忆，在一个破败聚落里重新站住脚。

几个核心方向如下：

- 聚落先救了主角，但不会立刻信任主角；Day1 的围观、带路、疗伤和晚饭冲突，都是这种关系的开场。
- 劳动不是刷资源，而是主角争取留下来的方式；砍树、采石、开垦、播种、浇水和制作共同服务这条生活线。
- 工作台不只是合成 UI，它连接生产、记忆和主角身份，是后续生产链与叙事线的交汇点。
- 聚落复兴不是纯数值成长，而是设施、居民日常、资源循环和剧情关系一起变化。
- 探索、钥匙、矿洞、四季资源和工具成长会逐步把 Day1 的基础劳动拉长为长期经营。

## 5. 推荐阅读路线

### 5.1 面试官快速阅读

1. 看 `README.md` 和演示视频。
2. 读 `01_总览.md`，理解项目不是单功能 Demo。
3. 读 `03_交互系统.md` 和 `04_剧情NPC.md`，看系统如何接到 Day1 体验里。
4. 如果对方追问项目状态，再补看 `08_进度总表.md`；它是接手状态表，不建议作为作品第一屏。

### 5.2 策划向阅读

1. `01_总览.md`
2. `02_经营成长.md`
3. `03_交互系统.md`
4. `04_剧情NPC.md`
5. `08_进度总表.md`

这条路线适合看《Sunset》的核心玩法、长期成长和叙事结构。

### 5.3 开发接手阅读

1. 先读 README，知道当前公开试玩版的玩家路线。
2. 再读本索引和 `08_进度总表.md`，知道哪些是当前试玩、哪些是后续设计。
3. 然后转到 `.kiro/about/01_系统架构与代码全景.md`，进入代码、资源和工程结构。

## 6. 维护口径

这套策划案后续继续按主题维护，不再把正式内容长期散落在一次性总结、锐评或临时线程记录里。

更新时遵守三条原则：

1. 新设计先落到对应主题卷，再回到 `08_进度总表.md` 更新状态。
2. 当前试玩已实现、已有运行时承载、后续设计愿景三类内容要分清。
3. 如果文档与 README 的公开试玩口径冲突，先修文档，不让旧说明拖累作品展示。
